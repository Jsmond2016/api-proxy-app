# 微信开发者工具 Apifox Mock 代理修复 需求文档

## 开发分支

`main`

## 背景与目标

本项目目标是提供一个 macOS 桌面代理工具，让微信开发者工具的 HTTP/HTTPS 请求在不修改小程序业务代码、构建配置或请求封装的前提下，经本地代理选择性转发到 Apifox Mock。

桌面应用参考项目 `/Users/huangjing/Desktop/MyCode/github/api_proxy_tool_ext` 的 Apifox 项目连接、OpenAPI 导出、Tag 筛选、规则生成、接口启停和 Mock Token 处理方式，但网络拦截载体由浏览器扩展的 `declarativeNetRequest` 改为 Tauri + Rust 本地 HTTP/HTTPS 代理。

2026-08-27 对当前安装包和代码进行复核后确认：现有版本主要是 UI 原型和局部代理技术验证，没有形成“配置真实项目 -> 同步 Tag -> 让微信开发者工具接入 -> HTTPS 解密 -> 命中规则 -> 转发 Apifox -> 实时查看结果”的可用闭环。本需求要求修复已发现的全部阻断问题，并以真实端到端证据作为交付标准。

## 现状审查结论

### 总体判断

当前文档声称从 `api_proxy_tool_ext` 迁移 Apifox Mock 能力，但代码只复用了“项目、Tag、规则、Mock 目标”等表层概念。参考项目中已经存在的项目 ID 导出、Mock Token、可选 Tag 获取、合并/覆盖和规则启停语义未完整迁移；桌面代理特有的 CA 安装、客户端接入和端到端验证也未完成。因此当前安装包不能作为可用 MVP 交付。

### 问题与证据

| 问题 ID | 严重性 | 问题 | 代码/运行证据 | 用户影响 |
| --- | --- | --- | --- | --- |
| P1 | 阻断 | 无法创建、编辑、删除真实联调项目 | `ProjectSidebar.tsx` 的新建、偏好设置、备份按钮无事件；`state.rs` 固化演示项目 | 用户只能使用假域名和演示规则，无法配置真实小程序后端 |
| P2 | 阻断 | Apifox 在线同步协议不完整 | 当前只对任意 `source_url` 发 GET；参考项目使用项目 ID、Bearer Token、API 版本头和 POST 导出请求 | 填写真实项目 ID 无法同步，在线模式名不副实 |
| P3 | 阻断 | 缺少 Apifox Mock Token | 当前数据模型和表单没有 Mock Token；参考项目会追加 `apifoxToken` 查询参数 | 需要 Mock Token 的云端 Mock 请求失败 |
| P4 | 阻断 | Tag 不能从 Apifox 获取且不能控制实际拦截 | 当前 Tag 为逗号文本；规则页 Tag 仅过滤表格，不更新 Rust 生效规则 | 无法按迭代 Tag 快速切换 Mock 接口 |
| P5 | 阻断 | HTTPS CA 流程不可操作 | 只生成 PEM；查看说明按钮无行为；`trusted` 永远为 `false` | 微信开发者工具不信任 MITM 证书，HTTPS 请求失败 |
| P6 | 严重 | 源域名字段未参与规则匹配 | `proxy/mod.rs` 仅按 method + path 匹配 | 相同路径的其他域名可能被错误转发，存在误拦截风险 |
| P7 | 严重 | 缺少真实项目的路径前缀与端口编辑 | UI 没有项目编辑入口，代理固定使用演示 Profile 的端口 | 无法限定拦截范围或解决端口冲突 |
| P8 | 严重 | 请求日志不实时 | Rust 只修改内存快照；前端仅初始化和按钮操作后读取快照，没有 event 或轮询 | 用户无法判断请求是否进入代理、命中规则或失败 |
| P9 | 严重 | 代理状态可能与真实监听状态不一致 | 启动命令在异步代理任务真正运行前写入 `running`；异步错误不推送 UI | 界面显示运行但端口可能不可用 |
| P10 | 严重 | 并发日志关联不可靠 | Handler 只保存一个 `pending_log_id` 和开始时间 | 并发请求可能把响应状态和耗时写到错误日志 |
| P11 | 严重 | OpenAPI 路径参数生成不可匹配规则 | 同步规则统一生成 `exact`，例如 `/users/{id}` 不会匹配 `/users/123` | 动态路径接口无法 Mock |
| P12 | 严重 | 同步会整体覆盖规则 | `sync_openapi` 直接替换 `profile.rules`，ID 由 method + 数组序号生成 | 手工规则、启停状态和稳定标识丢失 |
| P13 | 安全 | CA 私钥文件权限为 `0644` | 本机 `apifox-proxy-ca-key.pem` 实测为所有用户可读 | 本地 CA 私钥可能被其他用户读取 |
| P14 | 安全 | Token 没有 Keychain 持久化 | 当前仅临时传递 Access Token；无 Mock Token；无 `keyring` | 每次重复输入，且后续若直接写 JSON 会泄露凭据 |
| P15 | 一般 | 多个可见按钮没有功能 | 添加规则、批量操作、详情、清空日志、证书说明等无事件 | UI 暗示功能可用但点击无效果 |
| P16 | 一般 | 默认状态包含演示日志和假数据 | 本机落盘仍有 2 个演示 Profile 和 3 条演示日志 | 用户无法区分真实流量与样例数据 |
| P17 | 交付 | 测试无法证明核心工作流 | 现有 5 个单元测试不覆盖真实 HTTP/HTTPS、在线 Apifox、微信开发者工具和事件日志 | 编译及单测通过仍可能完全不可用 |
| P18 | 交付 | 未完成端到端验收就提前打包 | 旧方案文档明确记录 HTTP/HTTPS、CA 信任、微信接入和在线同步尚未验证 | 安装包不具备可交付质量 |

### 参考项目能力映射

| 参考能力 | 参考实现 | 桌面版要求 |
| --- | --- | --- |
| Apifox 在线导出 | 项目 ID + Access Token，POST 导出 OpenAPI | 由 Rust 发起同协议请求，返回文档摘要和可选 Tag |
| Mock Token | Mock URL 追加 `apifoxToken` | Token 存本地 Profile；同步规则目标显式携带后缀，转发时当前值覆盖旧值，日志脱敏 |
| Tag 同步 | 选择可用 Tag 后解析接口 | Tag 仅用于同步筛选和规则归类 |
| 规则启停 | 全局开关 + 单接口开关 | 代理运行状态 + 全局 Mock + 单规则启用共同决定生效 |
| 合并/覆盖 | 只替换 Apifox 来源接口，保留自定义接口 | 使用稳定来源 ID，提供合并/覆盖预览并保留用户状态 |
| 请求重定向 | 浏览器声明式规则 | Rust 代理按 host/path/method 匹配并改写至 Apifox |

## 目标用户工作流

1. 首次启动应用时没有演示项目和演示日志，展示创建真实项目的空状态。
2. 用户创建联调项目，填写项目名称、真实源域名、可选路径前缀和本地代理端口。
3. 用户选择 Apifox 在线模式，填写项目 ID、Access Token 和 Mock Token；或选择本地模式，填写 OpenAPI URL 和 Mock 前缀。
4. 应用验证连接并加载可用 Tag，用户多选当前迭代相关 Tag。
5. 应用展示将新增、更新、保留和删除的规则摘要，用户确认后同步。
6. 用户通过 Tag 控件选择当前激活的 Mock 范围，并可进一步启停单条规则。
7. 应用生成 CA，提供实际路径、打开证书和刷新信任状态操作；用户在 macOS 钥匙串中明确设为信任。
8. 应用展示微信开发者工具代理地址和接入步骤，用户将 HTTP/HTTPS 代理指向 `127.0.0.1:<port>`。
9. 用户启动代理；应用仅在监听成功后显示运行状态，并提供端口连通性结果。
10. 微信开发者工具发起请求；全局 Mock 开启且符合项目域名、路径范围和启用规则的请求转发至 Apifox，其余请求透传。
11. 工作台实时显示请求来源、匹配决策、目标、响应码、耗时和可脱敏的失败原因。

## 非目标

- 不修改微信小程序业务源码、环境文件、构建配置或请求封装。
- 不实现 VPN、内核扩展、透明代理或对不遵循显式/系统代理的软件强制抓包。
- 默认不自动修改 macOS 全局系统代理；用户在微信开发者工具中显式配置代理。未来若增加系统代理开关，必须单独确认权限、恢复和异常退出策略。
- 不绕过 certificate pinning。若目标客户端启用证书固定，应用只提供明确诊断。
- 本轮不迁移参考项目的权限点、迭代文档、浏览器扩展通信、自定义 JSON 响应和团队云同步。
- 本地测试包可使用 ad-hoc 签名；公开分发、Developer ID 签名和 Apple 公证需独立发布凭据与流程。

## 注意事项

- 代理和 CA 涉及敏感网络能力，必须限制监听 `127.0.0.1`，不得默认监听局域网地址。
- 不得在测试、截图、日志、异常或文档中记录真实 Access Token、Mock Token、Cookie、Authorization 或用户业务数据。
- CA 私钥不得导出到配置备份，不得以宽松权限写盘；删除/重建 CA 必须明确提示会使既有信任失效。
- 域名匹配必须先于路径和规则匹配，禁止仅按路径跨域拦截。
- Query 合并必须同时保留原请求参数和 Mock Token；不得用原请求 Query 覆盖目标 URL 自带参数。
- Tag 仅用于同步筛选和规则归类，不再承担运行时批量启停职责。
- 全局 Mock 状态与逐接口 `enabled` 必须独立持久化；切换全局开关不得覆盖逐接口选择。
- R15 会使同一 macOS 用户及能读取其应用数据目录的进程看到 Token 明文；用户接受该风险并可在 Apifox 等设置端随时废弃 Token。
- 已有 Keychain 条目不自动读取、迁移或删除，避免再次触发系统授权；用户可自行在“钥匙串访问”中清理。
- 所有可见操作必须有完整实现、禁用条件或移除，不保留无行为的按钮。
- Apifox Web 跳转优先使用 OpenAPI 的 `x-run-in-apifox`；仅在项目 ID 和数字接口 ID 均可靠时生成兜底链接，不得从 Mock URL 猜测接口页。
- 当前工作树已有用户文件 `pnpm-workspace.yaml` 和本轮新增 `mise.toml`，后续实现不得擅自删除或回退。
