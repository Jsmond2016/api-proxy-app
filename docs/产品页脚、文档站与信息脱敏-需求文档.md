## 2. 背景与目标

当前应用已具备项目管理、Apifox 在线同步、规则 Mock、本地响应预设、HTTPS 证书、请求日志、诊断和项目预设等能力，但没有统一的产品署名入口，也没有可独立浏览和发布的使用文档站。

本需求形成三个交付物：

1. 在桌面应用底部提供版本、项目和作者信息，交互参照 `quick-copy-ext` 的紧凑链接模式。
2. 基于现有已实现功能和现有需求/验收文档，建立 VitePress 文档站，面向使用者说明安装、配置、工作流、功能边界与问题排查。
3. 对会进入源码、应用界面、仓库文档和构建产物的接口 URL、真实域名、业务/公司信息与凭据进行分类、脱敏和持续检查，避免将联调数据带入公开内容。

不改变当前 HTTP/HTTPS 代理、Apifox 同步、配置持久化或规则匹配语义。

## 3. 现状依据

- 应用入口 [src/App.tsx](../src/App.tsx) 当前从 `ProxyHeader`、配置区、规则表到请求记录结束，没有应用页脚。
- 当前仓库没有 `.vitepress` 配置或 VitePress 依赖；现有使用材料分散在 `README.md`、`docs/项目需求文档.md` 与 `specs/`。
- 参考项目 `quick-copy-ext` 的 `PopupFooter` 采用“版本号 | 项目链接 | 作者链接”的单行样式；项目和作者链接均在外部浏览器打开。
- 本次静态基线扫描未发现已跟踪的 `.env`、证书/私钥文件，也未命中常见 AWS、GitHub、OpenAI、Slack Token 或 PEM 私钥格式。扫描不等同于凭据安全保证，仍须落实下述规则和自动检查。

## 4. 用户与核心流程

### 4.1 桌面应用署名

```text
使用应用
  -> 滚动至主工作区底部
  -> 查看当前版本、项目和作者信息
  -> 点击“项目”或“作者-…”
  -> 由系统默认浏览器打开对应公开页面
```

### 4.2 文档站

```text
访问文档首页
  -> 了解产品定位与安全边界
  -> 阅读安装和快速开始
  -> 按任务进入项目配置、Apifox 同步、Mock、证书或日志说明
  -> 需要时在故障排查页定位问题并回到应用处理
```

### 4.3 信息发布前检查

```text
新增源码、文档或截图
  -> 本地敏感信息检查
  -> 发现凭据、真实接口/域名或业务归属信息
  -> 按分类删除、替换为占位符，或移至运行时用户配置
  -> 构建文档站与应用
  -> 复检通过后交付
```

## 5. 功能需求

| ID | 需求 | 详细规则 | 验收标准 |
| --- | --- | --- | --- |
| F1 | 应用底部信息区 | 在主工作区末尾增加无嵌套卡片的紧凑页脚。内容按“版本号 | 项目 | 作者-<作者标识>”排列；版本继续使用当前 Tauri/构建版本来源。 | 正常和空项目状态均可见；窄窗口不遮挡请求记录，链接可换行但不重叠。 |
| F2 | 项目与作者外链 | 项目链接指向本仓库公开地址，作者链接指向仓库维护者公开主页。链接地址、显示文案和作者标识集中定义，避免散落硬编码。桌面运行时通过既有外部打开能力打开；网页预览中使用普通安全外链。 | 两个链接有明确 Tooltip，使用 `noopener`/`noreferrer`；点击后不替换应用窗口内容。 |
| F3 | VitePress 基础设施 | 新建独立文档站目录（建议 `docs-site/`），包含 `.vitepress/config.ts`、首页、导航、侧栏、静态资源与自定义主题样式；在 `package.json` 提供 `docs:dev`、`docs:build`、`docs:preview` 脚本。文档站构建产物不得提交。 | `pnpm docs:build` 成功；所有导航、侧栏和站内链接无死链；不影响现有 `pnpm build` 与 Tauri 打包。 |
| F4 | 文档首页与导航 | 首页直接呈现 Apifox Proxy 的用途、桌面应用边界、核心工作流和入口，不做营销落地页。顶栏至少提供“指南”“功能”“配置与安全”“开发”；侧栏按下表组织。 | 用户可在三次以内点击到任一核心功能说明；移动端导航可用。 |
| F5 | 功能使用说明 | 内容必须以当前实现为准，覆盖项目与 Tab、Apifox 在线同步/Tag/凭据、规则管理、全局与单接口 Mock、本地响应预设、项目预设导入导出、HTTP/HTTPS 代理与 CA、请求日志/诊断、真机模拟提示词和关闭恢复代理。 | 每项说明包含适用场景、前置条件、操作步骤、结果、限制或失败处理；不把未实现的 Local 模式、云同步、Windows/Linux 支持写成承诺。 |
| F6 | 配置、边界与排障 | 明确应用仅监听 loopback、不会自动修改系统或微信开发者工具代理、不能绕过 certificate pinning；说明 Token 的存储和展示限制、预设默认不导出凭据、日志不记录敏感 Body/认证头。提供代理未启动、CA 不受信任、Apifox 认证失败、端口冲突、未命中规则五类排障入口。 | 文档不引导用户共享 Token、证书私钥、真实请求或业务数据。 |
| F7 | 文档来源与维护 | 首页和各页面按主题链接或整合现有 `README.md`、`docs/项目需求文档.md`、`specs/需求-main/main-使用与验收文档.md`、项目预设需求及本地 Mock 需求。将可公开的稳定说明迁入文档站；历史方案可保留在 `specs/`，不直接作为用户手册。 | 同一功能的公开说明无互相矛盾的字段和流程；新增功能时同步新增/更新对应页面。 |
| F8 | 真实信息分类 | 建立“禁止公开”“必须占位”“允许保留但不得扩散”三类规则，覆盖源码、Markdown、截图 alt 文本、测试夹具、错误文本和构建产物。 | 规则在贡献说明或文档站维护说明中可见，且由脚本执行。 |
| F9 | 凭据与个人信息脱敏 | 禁止提交 Access Token、Mock Token、Authorization、Cookie、私钥、会话标识、真实邮箱/手机号和未授权个人信息。文档、截图和示例使用 `<ACCESS_TOKEN>`、`<MOCK_TOKEN>`、`example.test`、`<PROJECT_ID>` 等占位符。 | 对新增和变更文件运行检查；发现高置信度凭据时检查失败并输出文件与行号，不回显完整密钥。 |
| F10 | 域名、接口 URL 与业务信息脱敏 | 文档和展示示例不得包含真实源域名、内部 API 路径/参数、真实项目 ID、业务项目代号、公司/客户名称或内部网地址。真实运行目标只允许由用户在本地表单或导入文件中提供，且不写入日志/诊断。功能所必需的 Apifox 公共服务地址可保留在运行时代码，但不得带真实项目 ID、Token 或内部路径。 | 公开文档只出现 `api.example.test`、`https://mock.example.test/<PROJECT_ID>` 等可识别的占位示例；应用 UI、日志和导出预设不泄露真实输入值以外的隐含业务信息。 |
| F11 | 历史数据清理 | 清理或泛化仓库中不再需要的历史演示项目标识、测试/迁移中的业务名称，以及文档内的具体 Mock 项目编号与路径。迁移判断应保留兼容行为，但使用非业务化标识或版本化迁移条件。 | 当前已知的历史演示标识不再出现在公开文档、界面文案或可发布源码中；替换后相关迁移测试仍通过。 |
| F12 | 自动化检查 | 增加可在无网络环境运行的敏感信息检查脚本，纳入现有 `check:source` 或独立 `check:privacy`，并在文档站构建前执行。检查排除锁文件、依赖目录、第三方许可证和必要的依赖源 URL；规则维护在可审阅的配置中。 | 对真实 Token、私钥标记、内部域名和禁止词的测试样例能失败；对 `example.test`、loopback 地址、必要的第三方服务根地址能通过。 |

## 7. 脱敏基线与处置

### 7.1 已识别项

| 分类 | 位置 | 风险判断 | 处置 |
| --- | --- | --- | --- |
| 历史业务标识 | `src-tauri/src/state.rs` 的旧配置迁移条件，以及主线验收文档 | 标识会暴露曾使用的业务项目命名。 | 替换为通用旧演示标识；保留对应迁移覆盖。 |
| 示例 Mock 地址与项目编号 | `specs/tauri-desktop-app/*`、项目预设示例 | 虽未发现 Token，但具体项目编号和路径不适合进入公开文档。 | 替换为占位符域名、`<PROJECT_ID>` 和通用资源路径。 |
| Apifox 服务根地址 | `src-tauri/src/apifox.rs`、默认 Mock 前缀生成处 | 属于运行功能依赖的公共第三方服务，不是凭据。 | 保留在实现层；文档只描述其用途或使用泛化示例，不复制固定服务地址。 |
| 仓库与维护者地址 | Git remote 与参考项目署名模式 | 用户明确要求在页脚展示，属于可公开产品元数据。 | 仅作为页脚常量和文档站公开链接使用；不与公司、邮箱或其他身份信息关联。 |

### 7.2 脱敏格式

| 数据类型 | 文档/测试示例 | 日志与诊断 |
| --- | --- | --- |
| 源站域名 | `api.example.test` | 显示为 `<SOURCE_HOST>`，或按现有规则不落盘。 |
| Mock/接口 URL | `https://mock.example.test/<PROJECT_ID>/orders` | 过滤 query 中 Token；不显示真实业务路径。 |
| 项目 ID | `<PROJECT_ID>` | 不展示。 |
| Access/Mock Token | `<ACCESS_TOKEN>`、`<MOCK_TOKEN>` | 完全移除，不使用部分掩码作为可复制值。 |
| Authorization、Cookie、Body | `<REDACTED>` | 完全移除。 |
| 公司、客户、业务线名称 | `示例项目` | 不记录。 |

## 8. 非目标

- 不将用户本地 Profile、规则、本地响应、日志、证书或预设文件上传到文档站。
- 不声称文档站提供在线代理、在线 Apifox 同步或账号服务。
- 不自动修改用户的系统代理、微信开发者工具设置或 macOS 钥匙串信任。
- 不以“脱敏”为由删除代理运行必需的第三方公共服务根地址；仅限制其传播范围并禁止与真实业务数据、Token 组合。

## 9. 验收与交付

1. 桌面应用在主工作区底部显示版本、项目和作者信息，项目/作者外链可用且不影响桌面窗口。
2. `pnpm docs:build` 和现有 `pnpm build`、`pnpm run check:source` 均通过；VitePress 页面、导航和站内链接可访问。
3. 文档站覆盖第 6 节的全部页面和第 5 节 F5、F6 所列功能边界。
4. 公开 Markdown、界面文案、示例、截图与测试夹具不含真实凭据、真实业务域名、公司/客户名称、项目 ID 或内部接口路径。
5. 新增敏感信息检查能拦截第 5 节 F9、F10 所列违规样例，同时不会误拦截 `example.test`、loopback 和必要的依赖元数据。
6. 修改后的 Rust 迁移、前端构建与现有代理测试通过；若替换历史标识影响持久化迁移，必须增加回归测试。

## 10. 已确认决策

- 页脚作者显示为 `作者-Jsmond2016`；项目链接使用本仓库公开地址，均按参考项目的外链交互实现。
- 本期文档站只要求本地构建与预览；发布域名、托管平台和公开策略留待后续独立决定。
- 历史项目标识的清理保留已发布版本的迁移兼容行为，并以泛化标识或版本化条件替代业务命名；实现时补充回归测试。
