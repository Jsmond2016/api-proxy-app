# 项目配置预设 开发方案文档

## 开发分支

`feature/项目配置预设`

## 方案概览

在现有 Tauri + React 桌面应用中新增独立的“项目预设”文件模型与工作流。Rust 后端负责从 `ProjectProfile` 投影出无运行状态的预设 JSON、解析和严格校验导入文件、探测端口并原子创建新项目；React 前端在项目工具栏的新建按钮左侧提供“项目预设”入口，负责导出选项、导入文件选择、非敏感配置预览以及最终创建表单。

导入不会调用 Apifox，也不会复制规则或本地响应。创建后的项目空规则、全局 Mock 关闭，用户按既有入口验证 Apifox 后选择 Tag 同步，或自行新增 Mock 接口。

## 技术决策

| 决策项 | 结论 | 原因 | 备选方案 |
| --- | --- | --- | --- |
| 预设边界 | 只导出 Profile 基础网络配置与 Apifox 连接/Tag；不导出规则、响应、日志、运行开关或内部 ID | 符合“快速创建后按 Tag 或手动新增”的目标，防止错误复用旧 Mock 行为 | 直接导出完整 Profile：风险高，且应作为独立备份功能设计 |
| 格式版本 | 使用 `kind: apifox-proxy-project-preset` 和独立 `formatVersion: 1` | 可对外稳定演进，不耦合本地状态迁移 | 复用 `schemaVersion`：会使外部文件兼容性受内部状态影响 |
| 凭据 | 默认排除，明确勾选并二次确认才导出明文 Token | 可安全共享预设，同时保留受控快速配置路径 | 永不导出：安全但增加团队初次配置成本；自定义加密：无法在无密钥管理时保证安全 |
| 文件访问 | 使用 Tauri 官方 dialog/fs 插件，仅授予 JSON 文件选择和保存所需能力 | 保持桌面端用户可见文件选择与最小权限 | 让前端直写路径：无法满足桌面安全边界 |
| 校验与持久化 | 后端解析、校验和创建；前端不直接写状态文件 | 统一可信校验边界，保证失败原子性 | 纯前端解析：容易绕过校验并产生状态不一致 |
| 端口冲突 | 创建前同时检查其他 Profile 和系统监听端口，要求用户手动修改 | 保证微信开发者工具配置和实际监听端口一致 | 自动选取端口：用户代理设置可能仍指向旧端口 |
| Apifox 动作 | 导入只保存连接配置和建议 Tag，不验证、不同步、不启用 Mock | 避免意外网络副作用和凭据失败影响创建 | 导入时自动同步：不可预测、改变现有确认流程 |

## 注意事项

- 新项目必须生成新的 Profile ID，且初始 `rules`、`localResponses` 为空，`globalMockEnabled` 为 `false`。
- Access Token、Mock Token 绝不能出现在日志、Toast、诊断、错误上下文、预览文字或导出结果摘要中。
- 文件最大 256 KB，导入失败不写入 `desktop-state.json`，不留下半成品 Profile。
- 持久化模型新增字段必须提供向后兼容默认值或迁移；预设格式版本不可复用本地 `schemaVersion`。
- 文件能力和 Tauri permissions 使用最小授权；不实现远程文件、目录拖拽、云端预设库或自动分享。
- 不修改当前 Apifox 验证与同步语义；导入后仍由用户主动发起。

## 编码规范

- 所有新增或修改的 `.js`、`.ts`、`.tsx`、`.jsx`、`.mjs` 文件，格式化后单文件不得超过 500 个物理行；超过时按组件、Hook、纯函数或模块职责拆分。
- 代码保持精简，禁止重复代码；可复用的渲染、数据转换或业务逻辑按合理边界抽离。
- 禁止使用三元运算符；条件渲染优先采用 `renderXxx` 函数、哈希映射、`switch`、`if` 或提前返回。
- 禁止反向引用和双向引用。组件、模块和依赖只能从内向外单向引入；通过提取共享下层模块、调整职责边界或依赖注入消除循环依赖与层级反向依赖。
