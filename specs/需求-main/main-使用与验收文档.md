# 微信开发者工具 Apifox Mock 代理 使用与验收文档

## 1. 安装前提

- macOS，微信开发者工具已安装。
- 有权访问目标 Apifox 项目，并准备项目 ID、Access Token。
- 若 Apifox Mock 项目要求鉴权，准备 Mock Token。
- 明确小程序真实请求域名，例如 `api.dev.example.com`。

Token 填写在项目连接表单中，并随 Profile 写入应用数据 JSON。同步后的 Apifox 规则目标会显式包含 URL 编码后的 `apifoxToken`；请求日志和运行诊断仍会移除 Token。

## 2. 创建联调项目

1. 启动 `Apifox Proxy.app`。
2. 点击左侧“联调项目”旁的新增图标。
3. 填写项目名称。
4. 填写一个或多个真实源域名；只填 host，不要填 API path。
5. 可选填写路径前缀，例如 `/api`。
6. 设置未被占用的本地端口，例如 `8899`。

域名匹配先于规则匹配。不同域名上的相同路径不会被误转发。

## 3. 连接 Apifox 并同步 Tag

### 在线项目

1. 选择“在线项目”。
2. 填写 Apifox 项目 ID、Access Token、可选 Mock Token。
3. Mock 前缀可以留空，应用会按项目 ID生成默认 Apifox Mock 地址；非默认环境应填写完整 `https://...` 前缀。
4. 点击“验证连接”；验证成功后才会出现可搜索的多选 Tag 下拉框。
5. 从下拉框选择本次要同步的一个或多个 Tag。
6. 点击“确认 Tag 并拉取接口”。
7. 核对接口 method/path 预览以及新增、更新、删除、保留数量。同步固定替换 Apifox 来源规则，不删除手工创建或导入的规则。
8. 点击“确认同步这些接口”后才会写入规则；新生成的 Apifox 规则默认开启。

### 本地 URL

1. 选择“本地 URL”。
2. 填写可通过 HTTP GET 访问的完整 OpenAPI JSON URL。
3. 填写完整 Mock 前缀。
4. 后续验证、Tag 选择和同步步骤与在线项目相同。

Tag 只用于同步筛选和接口归类。接口同步后，在“Mock 接口”标题右侧使用全局 Mock Switch 控制整体拦截；每条接口仍保留独立开关。关闭全局 Switch 不会清空或改写逐接口状态。

Mock 接口列表固定高度并在内部滚动。请求路径与 Mock 目标支持自动换行；从 Apifox 同步且能识别接口页的请求路径可点击，并通过系统默认浏览器打开对应的 Apifox Web 页面。

每条规则右侧均可编辑或删除，删除前会显示应用内确认。点击“重置列表”并确认后，将清空当前项目的全部规则和已同步 Tag；项目连接、Access Token、Mock Token、Mock 前缀和全局 Mock 开关保持不变。

## 4. 配置 HTTPS CA

1. 点击“生成 / 读取”。
2. 点击文件夹图标，用系统应用打开 CA 证书。
3. 将证书导入 macOS 钥匙串。
4. 在“钥匙串访问”中找到 `Apifox Proxy Local CA`，将信任设置为“始终信任”。
5. 回到应用点击刷新图标，确认状态变为“已生成并受系统信任”。

应用不会自动取得管理员权限或静默修改系统信任。CA 私钥保存在应用数据目录，权限固定为 `0600`，不要复制或分享。

## 5. 接入微信开发者工具

1. 在应用中点击“启动代理”，确认状态为 `running`。
2. 打开微信开发者工具的代理设置。
3. 选择手动代理。
4. HTTP 和 HTTPS 均填写应用展示的地址，例如 host `127.0.0.1`、port `8899`。
5. 保存设置后，在小程序中触发目标接口。
6. 回到应用查看“接入检查”和“请求记录”。

不要只启动网页预览。只有 Tauri 桌面进程会监听端口、读取本地项目配置和处理 CONNECT。

## 6. 判断请求结果

| 日志状态 | 含义 | 下一步 |
| --- | --- | --- |
| 已 Mock | 全局 Mock、host、路径、Method 和接口规则全部命中 | 检查目标 URL、状态码和响应耗时 |
| 透传 | 请求进入代理但未命中规则或全局 Mock 已关闭 | 查看 stage：`host`、`path-prefix`、`global-switch` 或 `rule` |
| 失败 | 目标改写或 upstream 请求失败 | 检查 Mock 前缀、网络、Token 和 Apifox Mock 状态 |
| 无日志 | 请求没有进入代理 | 检查微信开发者工具代理地址、代理是否 running |

请求日志最多保留 500 条，不持久化 Body、Authorization、Cookie 或 Token。URL 中的 `apifoxToken` 会被移除后再展示。

“运行诊断”保留最近 100 条应用操作结果。连接验证、Tag 接口预览、同步、项目删除、规则修改、证书和代理启停都会记录开始、成功或 Rust 返回的失败原因；可复制后用于问题定位，内容不会包含表单中的 Token。

所有写操作同时显示 Toast。连接验证成功后，项目 ID、本地 OpenAPI URL、Mock 前缀、Access Token 与 Mock Token 会立即写入 Profile 配置；当前会话和应用重启后均保留并在密码输入框中回显。

## 7. 人工验收清单

- [ ] 首次启动不出现 `wx-retail`、`wx-member` 或演示日志。
- [ ] 项目创建、编辑、切换、删除和重启恢复正常。
- [ ] 在线 Apifox 验证能发现真实 Tag。
- [ ] Mock Token 在同步和重启后保留；同步生成的 Apifox 规则目标包含 `apifoxToken`，请求日志不显示 Token。
- [ ] 同步前 diff 数量符合预期，自定义规则不会被删除。
- [ ] 任意来源规则均可单独删除；重置列表后规则和已同步 Tag 清空，连接信息与 Token 保持不变。
- [ ] 关闭全局 Mock 时所有接口透传，且逐接口开关状态不变；重新开启后恢复原逐接口选择。
- [ ] 动态路径如 `/orders/{id}` 能命中 `/orders/42`。
- [ ] 相同路径但错误 host 不会 Mock。
- [ ] 微信开发者工具 HTTP 请求能命中 Mock。
- [ ] 微信开发者工具 HTTPS 请求能通过受信任 CA 命中 Mock。
- [ ] 未命中请求能够访问原始服务。
- [ ] GET query、POST body 和必要业务 header 保持正确。
- [ ] 停止代理后端口释放，端口冲突时 UI 明确报错。

## 8. 故障恢复

- 代理启动失败：编辑项目更换端口，或停止占用该端口的进程。
- HTTPS 报证书错误：重新打开 CA，确认导入的是当前应用展示路径下的证书，并刷新信任状态。
- Apifox 返回 401/403：重新填写 Access Token 后验证并同步；新值覆盖该项目配置。
- Mock 返回鉴权错误：重新填写 Mock Token 并同步；所有 Apifox 来源规则会刷新 `apifoxToken` 后缀。
- 配置损坏：应用数据目录保留最近一份 `desktop-state.json.bak`，恢复前先退出应用。
- 需要恢复正常网络：停止应用代理，并在微信开发者工具中关闭手动代理；应用从不修改 macOS 全局代理。
