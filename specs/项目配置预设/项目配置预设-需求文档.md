# 项目配置预设 需求文档

## 开发分支

`feature/项目配置预设`

## 文档状态

已实现，待 CR。本文件定义产品需求、交互和数据契约；代码实现与提交状态以开发方案和验证记录为准。

## 背景与目标

当前用户新建联调项目后，需要分别填写真实源域名、路径前缀、本地代理端口以及 Apifox 在线项目配置，之后再按 Tag 同步接口或手动新增 Mock 接口。相同业务线、环境或团队成员之间，这些基础配置高度重复，配置错误又会直接造成代理无法命中或 Apifox 同步失败。

新增“项目预设”能力，允许用户将一个项目的基础配置导出为可分享的 JSON 文件，其他用户导入后快速创建新的项目。创建出的项目保留独立身份，用户可立即选择以下任一方式开始 Mock：

1. 连接预设中的 Apifox 项目，选择 Tag 后同步接口。
2. 在空项目中手动新增自定义 Mock 接口，并按需绑定本地响应预设。

本期目标是减少重复录入和配置偏差，不把项目预设设计成完整项目备份或规则迁移工具。

## 用户与核心流程

目标用户为使用 Apifox Proxy 进行微信小程序联调的开发者，包括个人在多环境复用配置、团队成员之间共享联调基线两类场景。

```text
配置完成的项目
  -> 项目预设
  -> 导出基础配置 JSON
  -> 文件共享
  -> 其他用户导入并预览
  -> 填写新项目名称 / 处理端口冲突 / 确认凭据
  -> 创建新的空项目
  -> 按 Tag 同步 Apifox 接口，或手动新增接口
  -> 开启 Mock 联调
```

## 范围与术语

| 术语 | 定义 |
| --- | --- |
| 项目 | 当前应用中的 `ProjectProfile`，包含运行配置、接口规则、本地响应及运行开关。 |
| 项目预设 | 用于创建新项目的可移植基础配置 JSON，不等同于项目完整备份。 |
| 导出来源项目 | 用户在导出时选择的当前项目；仅抽取允许进入预设的字段。 |
| 导入预览 | 对预设文件做本地格式、版本和字段校验后，在创建前展示最终将写入的配置。 |
| 凭据 | Apifox Access Token 与 Mock Token，属于敏感信息。 |

## 产品设计

### 信息架构与入口

- 在项目 Tab 工具栏中，将名为“项目预设”的按钮放在“新建项目”按钮左侧；按钮使用图标加文字，提供清晰 Tooltip。
- 点击后打开“项目预设”弹框，默认展示两个主操作：`导入预设` 与 `导出当前项目为预设`。
- 当前没有活动项目时，保留“项目预设”按钮并允许导入；导出操作置灰并说明需先选择项目。
- 代理启动、停止或切换中的现有禁用规则同样适用于预设的创建导入动作，避免导入时与活动端口生命周期竞争；已经打开的预设弹框可取消。
- 本期不建立应用内“预设库”、云端同步、账号权限或自动共享。预设以用户显式选择的本地 JSON 文件导入、导出。

### 导出预设

1. 用户点击“导出当前项目为预设”。
2. 弹框展示来源项目名称，并要求填写预设名称；默认值为“{项目名称} 预设”。可选填写描述，用于团队说明环境、用途和维护人。
3. 弹框显示将导出的基础配置清单：源域名、路径前缀、建议端口、Apifox 项目 ID、Mock 前缀、已选择的 Tag。
4. 凭据默认不包含。用户可显式勾选“包含 Apifox 凭据”，确认二次风险提示后才允许将 Access Token、Mock Token 写入文件。
5. 用户选择保存路径后，应用生成扩展名为 `.apifox-proxy-preset.json` 的 UTF-8 JSON 文件，并提示导出成功及是否包含凭据。
6. 导出文件不得包含任何项目接口规则、本地 Mock 响应、请求日志、证书、项目内部 ID、运行状态或其他项目数据。

### 导入预设并创建项目

1. 用户点击“导入预设”，选择一个 `.apifox-proxy-preset.json` 文件。
2. 应用在写入前完成格式、格式版本、字段类型、域名、路径前缀和端口范围校验；读取失败、文件过大、格式不支持或字段非法时，不创建项目并展示可理解的错误。
3. 校验通过后展示导入预览。用户必须填写新项目名称；默认使用预设建议项目名并追加可编辑后缀，确保不与现有项目产生歧义。
4. 展示源域名、路径前缀、建议端口、Apifox 项目 ID、Mock 前缀、Tag。Access Token 与 Mock Token 只显示“已包含/未包含”，不显示明文。
5. 对端口执行本地冲突检查：若已被本应用其他项目占用或系统端口已占用，用户必须修改端口后才能创建。不得静默修改端口。
6. 对凭据执行以下处理：
   - 文件未包含凭据：允许先创建项目；在 Apifox 同步时提示填写必要凭据。
   - 文件包含凭据：默认导入并在表单中以掩码回显；用户可在确认前清空或替换。
7. 点击“创建项目”后，应用新建独立项目并自动切换为活动项目。新项目初始没有接口规则和本地响应预设，`globalMockEnabled` 为关闭。
8. 创建成功后关闭弹框。若预设带有 Apifox 项目 ID，在主界面突出显示“连接 Apifox”入口；用户自行验证连接、选择 Tag 并确认拉取接口。不得在导入过程中自动请求 Apifox 或自动同步接口。

### 创建后的 Mock 路径

- Tag 路径：用户打开 Apifox 面板，验证连接，选择预设建议的 Tag（如文件未声明 Tag，则由当前 Apifox 文档决定），预览后确认同步。
- 自定义路径：用户在接口规则区手动新增 Mock 接口，并按现有能力配置匹配规则、目标 URL 或本地响应预设。
- 导入完成但尚无规则时，应用必须保持安全透传，不能因为项目已有 Apifox 配置而拦截请求。

## 预设数据契约

### 文件格式

- MIME 类型为 `application/json`，编码为 UTF-8。
- 文件扩展名建议为 `.apifox-proxy-preset.json`；导入时以 JSON 内容和顶层标识校验为准，不只依赖扩展名。
- `formatVersion` 从 `1` 起独立演进，不复用应用本地状态的 `schemaVersion`。
- 首期只支持单个预设文件，不支持一次导入多个预设，也不支持 ZIP、远程 URL 或拖放目录。
- 文件大小上限为 256 KB；超过上限直接拒绝读取。

```json
{
  "kind": "apifox-proxy-project-preset",
  "formatVersion": 1,
  "metadata": {
    "name": "会员测试环境",
    "description": "用于会员小程序联调",
    "exportedAt": "2026-09-10T09:00:00.000Z",
    "exportedByAppVersion": "0.1.58"
  },
  "project": {
    "suggestedName": "会员测试环境",
    "sourceHosts": ["api-test.example.com"],
    "pathPrefix": "/api",
    "suggestedPort": 8899,
    "apifox": {
      "mode": "online",
      "projectId": "123456",
      "mockPrefix": "https://m1.apifoxmock.com/m1/123456-0-default",
      "selectedTags": ["会员", "登录"]
    }
  },
  "credentials": {
    "included": false
  }
}
```

当用户明确选择包含凭据时，`credentials` 可额外包含 `accessToken` 和 `mockToken`。该字段是明文 JSON，必须在导出与导入界面明确标识风险；应用不得尝试自定义加密或假装文件安全。若未来需要无感团队分发凭据，应另行设计系统钥匙串或团队密钥管理方案。

### 字段归属

| 分类 | 字段 | 导出 | 导入后的行为 | 理由 |
| --- | --- | --- | --- | --- |
| 预设元数据 | 格式标识、版本、名称、描述、导出时间、导出应用版本 | 是 | 用于识别、展示和兼容性校验 | 便于共享与后续演进。 |
| 项目基础配置 | 源域名、路径前缀、建议端口 | 是 | 创建前可编辑；写入新项目 | 是代理命中和监听的必要基线。 |
| Apifox 配置 | 在线模式、项目 ID、Mock 前缀、已选 Tag | 是 | 写入新项目；Tag 只作为同步建议，不自动拉取接口 | 满足快速配置 Apifox。 |
| Apifox 凭据 | Access Token、Mock Token | 默认否，可显式包含 | 可编辑后写入新项目 | 减少敏感信息泄漏。 |
| 项目身份 | `profile.id`、活动项目 ID | 否 | 后端新生成 ID | 导入必须创建独立项目。 |
| Mock 规则 | Apifox、Custom、Imported 规则及启停、优先级 | 否 | 新项目为空 | 避免旧环境路径、目标和接口状态被误复用。 |
| 本地响应 | 响应预设及规则引用 | 否 | 新项目为空 | 预设不是项目备份；避免携带业务响应数据。 |
| 运行状态 | 全局 Mock 开关、活动 Tag、代理状态、日志、证书 | 否 | 全局 Mock 关闭 | 确保新项目默认安全透传。 |

## 功能需求与验收标准

| ID | 需求 | 验收标准 | 状态 |
| --- | --- | --- | --- |
| R1 | 在“新建项目”左侧提供“项目预设”入口 | 正常与空项目状态均可见；可打开预设弹框；导出在没有活动项目时不可用；按钮遵循代理切换期间的禁用策略 | 已实现 |
| R2 | 从当前项目导出基础配置预设 | 导出的 JSON 满足固定 `kind` 与 `formatVersion`；包含网络、Apifox 和 Tag 配置；不含规则、响应、日志、证书、内部 ID、运行开关及默认排除的 Token | 已实现 |
| R3 | 受控导出与导入 Apifox 凭据 | 默认文件不含 Token；勾选并二次确认后才允许含明文 Token；导入预览不显示 Token 明文，可清空或替换；日志、Toast、诊断和错误不泄露 Token | 已实现 |
| R4 | 校验并预览预设文件 | 支持首期格式版本；拒绝非法 JSON、错误标识、未知版本、超限文件和非法字段；任何失败都不修改本地项目数据；成功时完整展示将创建的非敏感配置 | 已实现 |
| R5 | 从预设创建独立项目 | 必须填写可编辑的新项目名称；创建项目具备新 ID，使用用户确认后的域名、路径、端口和 Apifox 配置；冲突端口必须修正后才能继续；成功后自动切换为活动项目 | 已实现 |
| R6 | 新项目默认安全、可继续配置 | 不复制接口规则、本地响应、运行开关或日志；全局 Mock 默认关闭、规则为空；用户可随后验证 Apifox 并按 Tag 同步，或手动新增接口 | 已实现 |
| R7 | 数据兼容与失败原子性 | 本地 `schemaVersion` 升级后旧项目可正常加载；不支持的预设版本给出升级提示；导入的校验、端口检查和写入失败时均不生成半成品项目 | 已实现 |

## 交互与错误口径

| 场景 | 行为 |
| --- | --- |
| 导入文件不是预设 | 显示“不是 Apifox Proxy 项目预设文件”，不创建项目。 |
| `formatVersion` 高于当前支持版本 | 显示当前应用无法识别该预设版本，建议升级应用；不降级猜测解析。 |
| 文件缺少 Token | 可继续创建；Apifox 面板在连接验证时按现有规则要求填写。 |
| 预设中的 Tag 已在远端不存在 | 导入仍成功；后续验证连接时用远端 Tag 集合过滤并提示用户重新选择。 |
| 导出时项目尚未配置 Apifox | 允许导出网络基础配置；Apifox 字段为空，导入后用户补填。 |
| 导入端口占用 | 显示冲突来源（本应用项目或系统占用，如可识别）；不自动改端口。 |
| 同名项目 | 允许用户继续使用同名，但创建页应提示已有同名项目；项目 ID 仍独立。 |
| 导出写文件或导入读文件失败 | 保留当前弹框和用户已填写内容，展示错误；不改变本地项目配置。 |

## 非目标

- 不把项目预设做成完整项目、规则、本地响应或请求日志的备份与迁移。
- 不在导入阶段自动连接 Apifox、自动验证 Token、自动同步 Tag 或自动开启全局 Mock。
- 不提供预设云端同步、账号体系、团队权限、预设市场、远程 URL 导入或自动分享。
- 不导出或导入 CA 证书、私钥、代理运行状态、系统代理设置。
- 不承诺 Token 加密的文件交换能力；本期仅支持用户知情下的明文可选导出。

## 技术与数据约束

- 预设格式由 Rust 后端解析、校验并创建项目，前端只负责文件选择、表单编辑和预览，防止绕过校验直接写入状态文件。
- 文件选择与保存应使用 Tauri 的受限文件对话框能力，并限制可见扩展名；相关 capability 权限须遵循最小授权。
- 创建逻辑应复用现有项目输入校验、端口可用性检查和原子持久化能力；单次命令完成校验和写入，失败不留下配置变更。
- 新增模型字段需提供 `serde(default)` 或显式迁移，保证现有 `desktop-state.json` 可加载；预设文件版本与本地 `schemaVersion` 独立维护。
- 所有 Token 继续遵守现有脱敏约束，禁止写入请求日志、诊断记录、Toast、错误上下文或导出成功摘要。

## 待评审决策

1. 本文建议预设默认不包含 Token，同时允许明确勾选后明文导出。若团队有统一安全凭据分发机制，可改为“永不导出 Token”，由每位使用者在导入后填写。
2. 本文建议首期不导出任何 Mock 规则和本地响应，确保它是“项目初始化模板”。若后续需要复用固定接口集合，应增加独立的“规则包”能力，而不要扩大项目预设职责。
3. 本文建议保留预设中的建议端口并要求用户解决冲突，不自动分配端口，以免微信开发者工具的代理配置与应用实际监听端口不一致。
4. 本文建议导入后不自动请求 Apifox，既避免网络和凭据副作用，也让用户有机会检查配置。Tag 的有效性在用户主动验证连接时再以远端数据为准。
